# CivicLens OpenSpec

These capability specifications define planned product behavior. They describe target requirements; they do not claim the corresponding providers, UI, AI analysis, spatial calculations, or integrations are implemented.

| Capability | Purpose |
| --- | --- |
| [site-selection](specs/site-selection/spec.md) | Establish a provenance-aware construction-site anchor. |
| [investigation-creation](specs/investigation-creation/spec.md) | Create a bounded investigation of one selected site. |
| [evidence-gathering](specs/evidence-gathering/spec.md) | Inventory evidence and provider availability honestly. |
| [construction-change](specs/construction-change/spec.md) | Produce structured, uncertainty-aware construction-change findings. |
| [spatial-investigation](specs/spatial-investigation/spec.md) | Analyze footprint/land-feature relationships without legal conclusions. |
| [government-record-cross-check](specs/government-record-cross-check/spec.md) | Compare available record evidence without inferring non-compliance from absence. |
| [civic-signals](specs/civic-signals/spec.md) | Correlate contextual civic/public signals with provenance. |
| [administrative-context](specs/administrative-context/spec.md) | Describe administrative context without enforcement or liability claims. |
| [evidence-backed-findings](specs/evidence-backed-findings/spec.md) | Present grounded findings and human-verification recommendations. |

The former complaint-intake, location-accountability, evidence-verification, and case-escalation specifications were superseded by the construction-site investigation pivot in ADR-007. Git history preserves their prior text; [the realignment matrix](../docs/PRODUCT-REALIGNMENT.md) records their treatment.
